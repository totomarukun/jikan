# TacTap 再設計 v2 — 方向ドキュメント (サイクル16〜)

> ステータス: ドラフト / 一部リサーチ待ち。実装はリサーチ結果を反映してから。
> 上位方針は `product-backlog.md`「根本改善ループ」、一次資料は `tactap-plan-v1.0.md`。

## 0. なぜ再設計するか (ユーザーの再定義)
これまでは **A/B 2択がUIの主役**で、相対データは「3票溜まったら出る集計」だった。
サイクル15で相対マップ(推移律ベース)を導入したが、入口はまだ A/B のまま。

**コア価値の再確認**: ユーザーが一番見たいのは「**用具の特徴が相対的に分かる**」こと。
- A/B 2択は**価値そのものではなく、相対データとレビューを生む手段**。UIの主役から降ろす。
- 入力(A/B・レビュー)は「**レビュー/データを見るために自然に求められる**」形にする(funnelの反転)。
- 画面遷移・IA・各ページを、相対理解を中心に作り直す。

## 1. funnel の反転 (最重要の設計転換)
**旧**: 入口=A/B出題 → 答える → (3票で)集計が見られる … 投稿が先、閲覧が後。作業感。
**新**: 入口=相対マップ/用具を探す → 見る → **もっと見たい所で自然に入力を求める** … 閲覧が先、貢献が後。

自然な入力トリガー(作業でなく「見たいから答える」):
- ある用具の「両方使った人のレビュー」を読もうとする → 「あなたも使ったことある? 体感を教えると、あなた基準の相対位置に翻訳されます」
- 自分のギア基準でマップを見る → 未接続の用具に「あなたの◯◯と比べてどう感じた?」のソフトな1問
- 候補を絞った最後に「で、どっち?」 → その2本のA/Bを促す(=最も意思決定に近い所で出題)
> 強制ゲートにしない。閲覧自体は常に可能(疎データでも推定+信頼度で何か返す)。入力は価値の解像度を上げる行為として置く。

## 2. 新しい IA / 画面遷移
- **ホーム = 用具を探す/相対マップ**: 最初に見えるのは用具の相対的な特徴。軸で並べ替え・絞り込み。
  (旧ホームの A/B 誘導は、サブ導線「今日の一問」程度に降格)
- **用具詳細ページ = ハブ**: その用具の
  - 軸別の相対位置(全体の中で / **あなたのギアと比べて**)
  - 両方使った人の定性レビュー(言葉)＋ レビュー動画リンク
  - 似た用具 / 乗り換え先候補 / 乗り換え元
  - 自然な貢献導線(「あなたも答える/レビューを書く」)
- **マイギア = 自分の原点**: 相対マップの基準、乗り換え検討の起点、使用遍歴(下記4)。
- **A/B(入力)**: 独立した大画面でなく、詳細ページ/マップ/絞り込みの文脈に**埋め込む**。
  「今日の一問」「この2本で迷う人へ」など文脈つきで surfacing。
- **SNS流入の着地**: 共有カード(マップ/ランキング/診断/ギア)→ 該当の詳細/マップに着地 → 貢献導線。

現行ページの扱い(案):
- `/` 作り直し(マップ中心) / `/map` をホームに昇格 or 統合
- `/equipment/[id]` をハブとして大幅強化
- `/play` は文脈埋め込み用の部品に分解(単独ページは残すが主役でない)
- `/switch` `/compare` `/battles` `/diagnosis` はマップ/詳細ページの機能として再配置・統合を検討
- `/gear` `/me` を「マイギア(原点+遍歴)」として再設計

## 3. 比較・特徴の評価軸 (リサーチ確定)
リサーチ結果(Revspin / 卓球ナビ / メーカー公称 / レビュー動画語彙)。出所は調査ログ参照。
**主観評価軸**と**客観フィルタ属性**を明確に分離するのが核心の設計指針。

- **ラバー 主観軸(推奨, 優先度順)**: スピード(弾み)★★★ / スピン(回転量)★★★ /
  コントロール★★★ / スポンジ硬度★★★ / 弧線の高さ★★ / 球持ち(食い込み)★★ /
  粘着性★★ / 耐久(寿命)★。
- **ラケット 主観軸(推奨)**: スピード(反発)★★★ / コントロール★★★ / 打球感(硬さ)★★★ /
  しなり(剛性)★★ / ブレード構成★★ / 重量★★ / スイートスポット★。
- **客観フィルタ属性(軸でなく属性。揺れない)**: 重量(g) / メーカー公称硬度(自社基準) /
  ブレード構成(単板/合板/カーボン等) / グリップ形状(FL/ST/AN) / 表面タイプ(裏/表/粒高) /
  原産国 / 価格。
- **設計上の必須注意**:
  - メーカー公称硬度は社間で直接比較不可(各社独自基準)。「メーカー公称(自社基準)」と
    明示するか、TacTap体感硬度(ユーザー相対判定)を別に持つ。**数値をそのまま横並びにしない**。
  - 同一ラバーでも厚さで性能が変わる → 比較は厚さを揃えるか属性として扱う。
  - コントロール/打球感/球持ちは主観で最も割れやすい → 単一スコアより分布・相対表示。
  - 「回転のかけやすさ」≠「最大回転量」。混同しないラベル設計。

現状の Comparison 列は overall/speed/spin/**control**/hardness/ballHold の6軸。
- **済(サイクル16)**: control を相対マップに露出(列は既存)。
- **次**: 弧線(arc)を新列 winnerArc として追加(schema + types Zod + 質問生成 + マップ)。
  粘着/原産国/表面タイプ/重量/価格は **Equipment 側の属性**としてフィルタに(相対軸にしない)。
> 軸が増えても A/B は「全軸一度に」でなく、見ている文脈で1軸ずつ問える設計を維持。

## 4. マイギア再設計 (リサーチ確定)
現状 `GearItem` は equipmentId/side/thickness/bladeEquipmentId/isCurrent/createdAt のみで簡素すぎる。
他ジャンルのギア管理(Strava My Gear/シューズ走行距離/ゴルフWITB/釣りタックル)と卓球の
使用用具文化(卓球ナビ選手DB・やりログ「ラケット+F/Bラバー+厚さ」)から確定。

**「Webで管理する理由」=返すコア価値(優先度順)**:
1. 自分基準の相対マップ/推薦のパーソナライズ(最優先, TacTapの核)
2. 乗り換え検討の精度(現構成+遍歴+感想メモ → あなたの遍歴に合う候補)
3. 張り替え時期リマインド(使用開始日 × 頻度。卓球は寿命概念が明確=80h/3-6ヶ月)
4. シェア用プロフィール(WITB文化。流入・口コミ動線)
5. 同構成ユーザーとの比較

**GearItem に足す項目(優先順)**:
- `usageStartedAt: DateTime?` (最優先) — 張替リマインドの起点。createdAt と別に「いつ貼ったか」。
- `note / replacedReason: String?` — 乗り換え遍歴の質的記録(価値#2)。
- `weightGrams: Int?` — 上級者のこだわり(カット後実測)。任意。
- `purchaseDate / purchasePrice: Int?` — 振り返り。任意。
- (低)補助剤/メンテ。後回し可。
> 入力負荷対策: ラバー名を選べば硬度・公称値・標準重量は Equipment DB から自動反映。
> side/thickness は String+Zod 規約(AGENTS.md)。新 enum 値は types.ts と両方更新。
> 現「isCurrent=true 集合=現構成 / false=過去遍歴」モデルは正しい。usageStartedAt を足すだけで
> 「現用ラバーの経過月数 → リマインド」最小版が成立。

## 5. SNS 設計 (リサーチ確定)
卓球層は「用具ランキング・選手使用用具・乗り換え・試打比較」に強い関心(WRM/ぐっちぃ、卓球王国
月次売上ランキングのニュース化、卓劇屋ランキング)。診断シェアとX二択対決は実証済みのバズ機構。

**シェアしたくなるTacTap発コンテンツ(優先度順, 動的OGPカード)**:
1. **スタイル診断結果カード(◯◯タイプ)** — 「知りたい+見せたい」の二重欲求。最も拡散実証が強く
   登録動線(企画書M5)に直結。
2. **自分のギアカード(用具構成晒し)** — 卓球の既存「使用用具を見せる」文化に乗る。承認+仲間探し。
3. **相対マップカード(自分の位置づけ)** — 「意外なデータ/パーソナルな自分の◯◯」。ランキング文化と接続。
4. AB対決の自分の回答シェア — 軽い立場表明。X二択文化に乗る。

**公式アカ投稿(気になる順, ルーティン化)**: ①今日の一問(AB X投票) ②週次・急上昇ランキング
③意外な比較結果 ④乗り換え事例ハイライト ⑤週次・相対マップ更新 ⑥診断/レビューのUGC再循環。
トーンは企画書(軽妙・卓球愛)。禁止表現(絶対/No.1/最強)を避ける。

**SNS回答データの扱い(重要な指針)**: **X投票は流入・話題化に限定し、本体DBには混ぜない**。
自己選択/サンプリングバイアス・匿名重複・属性が紐づかない、で中立性(TacTapの核)が崩れるため。
信頼データはアプリ内AB(前提3問で属性が付き、1ユーザー1票を担保)で取り、X投票は「続きはアプリで
(スタイル別の結果が見られる)」の送客フックにする。投票結果を出すなら「n=◯, SNS投票のため偏りあり」と明示。

## 5.5 実装ロードマップ (優先順)
- **済 サイクル16-a**: ホームのfunnel反転(主役を用具マップに、A/Bを副導線へ)。「使い方」を
  「見る→自分基準→答える」に。
- **済 サイクル16-b**: 比較項目の見直し第一歩。control(既存列)を相対マップに露出。
- **次1**: 弧線(arc)軸の追加(schema+types+質問生成+マップ)。Equipment に属性(原産国/表面/重量/
  価格)を持たせフィルタ化(相対軸と分離)。
- **済 次2**: マイギア再設計。GearItem に usageStartedAt / note。現用登録時に貼付日を
  当日へ自動設定(摩擦ゼロでリマインド成立)。/gear を「現在の構成」と「これまで使った用具
  (遍歴)」に分割。各行で貼った日・メモをインライン編集(乗り換え理由の質的記録)。経過月数・
  約4ヶ月でのやわらかい張替リマインド。gear-reminder の純関数+テスト。
  - 残(後続): 重量(weightGrams)/購入価格、自動スペック反映、/me を「原点+遍歴」へ。
- **済 次3**: 用具詳細ページのハブ化。相対マップ上の軸別位置(全ラバー中の順位+支持本数)・
  あなたのギア基準の体感翻訳・両方使った人の体感・レビュー動画導線(YouTube検索)・シェア。
  - 残(後続): A/B を詳細/マップへさらに文脈埋め込み(単独主役の完全撤廃)。
- **済 次4(第一歩)**: SNSシェア資産。用具ページの動的OGカード(相対位置を1枚に)+ シェアボタン
  (Web Share→X)。SNS投票は本体DBに混ぜない方針を維持。
  - 残(後続): 診断/ギア/マップの専用OGカード、公式投稿フォーマットの運用。
- **後続 次1の残り**: Equipment に客観属性(原産国/表面タイプ/重量)を持たせフィルタ化。
- 各 next の着手前に **planning-anchor** で「コア価値に資するか/競合より良いか/疎データでも価値が出るか」を確認。
