# 本番スモークテスト (O1)

デプロイ直後に「本番が実際に動くか」を約10分で確認するチェックリスト。
独立評価サイクル(1〜27)が検証したコア機能とデータ正直さの不変条件を、
本番URL `https://<project>.vercel.app` に対して上から順に確認する。

前提: README「本番デプロイ」の手順でデプロイ済み。`DATABASE_URL` /
`DIRECT_URL` / `AUTH_SECRET` が設定されていること。

## 0. ビルド・起動
- [ ] Vercel のビルドログが成功（`build:deploy` = postgres generate → db push → seed → next build）。
- [ ] 用具マスタが投入されている: `GET /api/equipment?all=1` が **356件前後**を返す。
- [ ] `AUTH_SECRET` 未設定だと本番起動を拒否する設計。設定済みでトップが 200 を返す。

## 1. 閲覧フロー(登録なし)
- [ ] `/` が開き「両方使った人の比較／相対的に分かる」が伝わる。
- [ ] `/catalog` で用具一覧・検索(ひらがな/英/ローマ字)が動く。
- [ ] `/catalog?view=map` で分布が出る。「この軸で比較データのある◯本を表示中(残り◯本…)」の注記が出る(コールドスタートでは少数 or 空状態)。
- [ ] `/battles` がデータ無しなら「ランキングはこれから/集計中」と正直表示(空でも壊れない)。

## 2. オンボーディング〜回答
- [ ] `/onboarding` で前提3問 + マイギア登録ができる。
- [ ] マイギア無しで `/play` に行くと「まず使ったラバーを登録」ゲートが出る(いきなりイメージ質問を出さない)。
- [ ] 同じ面に2本以上のラバーを登録 → `/play` で「両方使ったことのある2本です」の実体験出題が出る。
- [ ] A/B回答が保存され、`answerCount` が増える(同一ペア×軸の再回答は revised で増えない)。

## 3. データ正直さ(最重要の不変条件)
- [ ] 実比較が3件未満の軸・用具は「少」グレー/「集計中」で、**数値を断定しない**(100%/0% の飽和表示が出ない)。
- [ ] 用具詳細 `/equipment/<id>` の順位は「**同じ種類のラバーの中で**」。表ソフトを裏ソフトと混ぜた順位にならない。
- [ ] 「比較N件(両方使ったM件)」の母集団ラベルが出る。

## 4. ラバー種類の分離(サイクル18-20)
- [ ] 表ソフトを現用にした状態で `/switch`・出題・分布の参照が**表ソフト同士のみ**(裏/粒高/アンチが混ざらない)。
- [ ] 種類違い(表×裏 等)に「スピンどっちが上?」のような無意味な出題が出ない。

## 5. 乗り換え検討 `/switch`(サイクル24-26)
- [ ] 現用ラバーを基準に候補が軸別差分つきで並ぶ。
- [ ] 各候補に「両方使った人 N件」(BOTH直接比較数)が出る。直接データの薄い候補は「データ少なめ/直接データなし・推定」。
- [ ] 軸チップの支持率%が、同じ対決の `/compare/<a>/vs/<b>?mode=custom&exp=both` の投票分布と**一致する**(母集団=両方使った人で揃っている)。

## 6. 絞り込み・診断
- [ ] `/compare/<a>/vs/<b>?mode=custom&exp=both` でURLから絞り込みが効く(SSRに反映・共有可能)。
- [ ] 10問回答後 `/diagnosis` でスタイル診断が出る。回答が弱いと「攻撃志向」等と断言せず中立 or 申告スタイルを尊重。

## 7. セキュリティ・整合性
- [ ] サインアップにパスワード(8文字以上)が必須。メールだけで他人データにアクセスできない。
- [ ] 別デバイスでログインすると匿名時のギア・回答が引き継がれる(primarySessionId)。
- [ ] `/battles`・診断の該当率など公開集計は「両方使った人(BOTH)」基準。匿名セッション量産で看板の数字が動かない。

## 完了後
- KPI計測(企画書13.2)を開始。Phase A(累計500回答・ユニーク50人)を目標にシードデータ獲得(企画書14.3 コーチ・専門店連携)へ。
- 不具合が出たら該当URL・操作・レスポンスを添えて `docs/product-backlog.md` に記録し、新しい評価サイクルでなく**実データでKPIを測る**局面であることを意識する(実装ループのクローズ宣言参照)。
