# ガチスペ デザインシステム (design.md)

デザイン判断の**単一の真実**。色・余白・コンポーネント・文言の迷いはここで解決する。
一次資料は企画書 `docs/tactap-plan-v1.0.md`（特に第10章ブランド）。本書はその実装版で、
矛盾する場合は企画書のブランド指針が優先。再設計の経緯は `docs/redesign-v2-direction.md`。

## 0. 方向性 (採用アesテティック)

**ミニマル・データ前面 (Geist / Linear 系)**。コア価値「用具の特徴が相対的に分かる」を、
装飾でなく**データそのものの可読性**で支える。判断軸:

- **影より線**: elevation は基本 1px ボーダー(`ring-1`)。影は overlay と主要 CTA のみ。
- **余白で区切る**: 罫線やカードの多重ネストより、余白とセクション見出しで構造を出す。
- **数値は等幅**: n・%・スコア・差分は JetBrains Mono。視線が数字に集まる。
- **色は意味だけに**: 緑/コーラルはブランドと「方向(▲▼)」に限定。地は off-white と charcoal。
- **正直さがデザイン**: データが薄いときは堂々と薄いと見せる（後述パターン）。誇張しない。

> アンチパターン: グラデ多用、絵文字での強調、影の盛りすぎ、根拠なき断定コピー。

## 1. Foundations (トークン)

すべて `src/app/globals.css` の `@theme` に CSS 変数として定義し、Tailwind v4 のユーティリティ
(`bg-tt-green` 等)として使う。生の HEX をコンポーネントに直書きしない。

### 1.1 カラー (企画書 10.3)

| トークン | HEX | 役割 |
|---|---|---|
| `tt-green` | #1A8917 | ブランドメイン / 主要CTA / 「▲高い・優位」 |
| `tt-coral` | #D85A30 | アクセント / 「▼低い・注意」 |
| `tt-deep-green` | #0F6E56 | soft-green 上のテキスト・見出し |
| `tt-deep-coral` | #993C1D | soft-coral 上のテキスト |
| `tt-soft-green` | #E1F5EE | 薄い強調背景(自分基準・肯定) |
| `tt-soft-coral` | #FAECE7 | 薄い強調背景(注意・データ不足) |
| `tt-charcoal` | #1A1A1A | 本文・見出し |
| `tt-gray70` | #5F5E5A | サブテキスト・補足 |
| `tt-gray30` | #B4B2A9 | ボーダー・無効・「データ少なめ」 |
| `tt-offwhite` | #FAFAF7 | ページ地 / セクション地 |

**セマンティック対応（使い分けの指針）**:
- 地: `tt-offwhite`(ページ) / `white`(カード) / `tt-offwhite`(カード内のネスト面)
- 罫線: `tt-gray30/30〜50`（`ring-1 ring-black/5` も可、ただし新規は `tt-gray30` 系に寄せる）
- 方向の色: 上=`tt-deep-green` / 下=`tt-deep-coral` / 同等=`tt-gray70`
- 確信度が低い: `tt-gray30` に縮約（色を出さない＝主張しない）

### 1.2 タイポグラフィ (企画書 10.4)

フォント: 見出し/本文 = Inter + Noto Sans JP、データ = JetBrains Mono(`font-mono`)。

| 用途 | クラス | px/行間 |
|---|---|---|
| Display (トップ見出し) | `text-3xl font-bold` | 30 |
| H1 (ページタイトル) | `text-2xl font-bold` | 24 |
| H2 (セクション) | `text-lg font-bold` | 18 |
| Body | `text-sm` | 14 |
| Caption (補足) | `text-xs text-tt-gray70` | 12 |
| Micro (バッジ/注記) | `text-[11px]` | 11 |

- **`text-[10px]` は新規禁止**（読めない・場当たり）。最小は `text-[11px]`。
- 数値・単位(n=, %, °, +12, ¥)は必ず `font-mono`。
- 太さは `font-bold`(見出し・強調) と通常の2段のみ。`font-medium` はナビ等の軽い強調に限定。

### 1.3 スペーシング

8pt グリッド準拠。Tailwind の `1=4px`。**カード内の基準は `p-4`(16px)**。

| 文脈 | 値 |
|---|---|
| カード内パディング | `p-4`（情報密度が必要なら `p-3`、ヒーロー級は `p-5`） |
| セクション間 | `mt-6`(24) / 大区切り `mt-8`(32) |
| 要素間（縦） | `space-y-2`〜`space-y-3` |
| チップ等の間隔 | `gap-1.5`〜`gap-2` |
| ページ左右 | `px-4`（`max-w-3xl` 中央寄せ。本文系は `max-w-md`） |

> 既存の `p-2.5`/`p-3.5` は段階に寄せて廃止していく（`p-3`/`p-4`）。

### 1.4 角丸 (radius)

少数に統一。用途で固定する（混在をやめる）。

| 用途 | クラス | px |
|---|---|---|
| ピル(チップ・バッジ・丸ボタン) | `rounded-full` | — |
| ボタン・入力・小カード | `rounded-lg` | 8 |
| カード・パネル | `rounded-xl` | 12 |
| 大きいヒーロー面 | `rounded-2xl` | 16 |

> `rounded-3xl` は原則使わない。既存の `2xl` 多用は段階的に `xl` へ寄せ、ミニマルに締める。

### 1.5 Elevation (影より線)

| レベル | 表現 | 用途 |
|---|---|---|
| 0 | `ring-1 ring-tt-gray30/40` | 既定のカード・パネル（影なし） |
| 1 | `ring-1 ring-tt-gray30/40 shadow-sm` | 重要カード・選択中 |
| 2 | `shadow-lg` + ボーダー | overlay / 固定フッター / 主要CTA |

- 既定は **0(線のみ)**。`shadow-sm` の乱用をやめ、情報の階層は余白で作る。
- 選択状態は影でなく**2pxリング**(`ring-2 ring-tt-green`)で示す。

### 1.6 モーション

定義済み（`globals.css`）: `animate-rise`(出現) / `animate-pop`(達成) / `animate-grow`(バー伸長)。

- 画面遷移・カード出現は `rise`。バー(相対位置/VersusBar)は `grow`/`bar-grow`。
- 200ms 前後・`cubic-bezier(0.22,1,0.36,1)`。**過剰な動きは避ける**（データの邪魔をしない）。
- `prefers-reduced-motion` を尊重（実装時にメディアクエリでアニメ無効化を追加）。

### 1.7 Z-index / ブレークポイント

- z: ヘッダー `z-20` / VS バッジ等の局所 `z-10` / 固定フッター・overlay `z-30`。
- モバイルファースト。`sm:` 以上で余白・段組みを足す。基準幅 `max-w-md`(本文) / `max-w-3xl`(全体)。

### 1.8 アイコン / ビジュアル

- 用具ビジュアルは `EquipmentVisual`(種類別の図像)に集約。新規の独自図は作らない。
- 線アイコンを基本（塗りは避ける）。サイズは 16/20/24 を基準。

## 2. コンポーネント (shadcn/ui ベース)

プリミティブは **shadcn/ui** を `src/components/ui/` に取り込み、見た目は本書のトークンで上書きする
(Radix のアクセシビリティはそのまま活かす)。アプリ固有の複合UIは `src/components/` に置く。

| コンポーネント | 種別 | shadcn 対応 | バリアント / 用法 |
|---|---|---|---|
| **Button** | プリミティブ | `button` | `primary`(緑グラデ→単色緑へ)・`secondary`(白+線)・`ghost`・`danger`(コーラル)。高さ `h-11`、`rounded-lg`、`font-bold`。1画面の primary は原則1つ |
| **Card** | プリミティブ | `card` | `white + ring-1`(既定 elevation0)。見出しは H2。ネスト面は `bg-tt-offwhite` |
| **Chip/Tag** | アプリ | (badge流用) | フィルタ・種類・基準切替。`rounded-full`、選択中=`bg-tt-deep-green text-white`、非選択=`bg-white ring-1` |
| **Badge** | プリミティブ | `badge` | `現用`/`基準`/`実体験`/`データ少なめ`。`text-[11px] font-bold rounded-full` |
| **Stat / Metric** | アプリ | — | 数値+ラベル。数値は `font-mono`。差分は方向色+符号(`+12`) |
| **VersusBar** | アプリ | — | A/B/SAME の割合バー。n表示必須。n<3 は集計中表示(後述) |
| **AxisBar(相対位置)** | アプリ | — | 0-100 の相対位置。支持<3 は `tt-gray30` に縮約し「データ少なめ」 |
| **EmptyState** | アプリ | — | 破線枠 `border-2 border-dashed border-tt-gray30/50`、正直な説明 + 次の一手の導線 |
| **Form (input/select)** | プリミティブ | `input`/`select`/`label` | `rounded-lg ring-1`、エラーはシステム側の謝罪トーン(§5) |
| **Tabs / Segmented** | プリミティブ | `tabs` | 一覧/分布/くらべる、軸切替。選択中をリングで明示 |
| **Dialog / Sheet** | プリミティブ | `dialog`/`sheet` | 基準ピッカー等。overlay は elevation2 |

**共通ルール**:
- 同じ意味の要素は必ず同じコンポーネントで（チップ・バッジ・空状態の手書き再実装をやめる）。
- ボタンのラベルは動詞で具体的に（「比較に答える」「乗り換えを検討」）。「送信」等の汎用語を避ける。

## 3. パターン (ガチスペ 固有の必須ルール)

### 3.1 データの正直さ（最重要・コア価値）
- **n<3 は断定しない**: VersusBar・相対位置・勝率は「集計中(あとX件)」または `tt-gray30` 縮約。
  「100%」「多数派」をn=1で出さない。
- **支持が薄い軸はグレー + 参考バッジ**: 方向(▲▼)は出してよいが数値(量)は確信が乗るまで出さない。
- **出所を偽らない**: 公称スペックは「各社基準・他社比較不可」を明記。推定は推定と言う。

### 3.2 ラバー種類の分離（サイクル18-20 の確定方針）
- 比較・順位・候補・出題・分布は**同じ比較可能グループ内**でのみ(`rubberGroup`)。表/裏系/粒高/アンチを混ぜない。
- 種類が関わる表示には種類ラベル(`EQUIPMENT_CATEGORY_LABELS`)を添える(裏ソフト/表ソフト/粒高/粘着/アンチ)。
- 順位コピーは「**同じ種類のラバーの中で** N本中M位」。

### 3.3 モバイルレイアウト
- 1カラム基本。主要操作は親指の届く下部に（固定フッターは elevation2）。
- 1画面1主目的。CTA は明確に1つ。スクロールで詳細へ。

### 3.4 自分基準 (パーソナライズ)
- 基準ラバーを置くと一覧・分布・くらべるが「自分基準(差分・近い順)」になる。基準は種類を固定する。
- 「現用」「基準」「実体験」はバッジで一貫表示。

## 4. ボイス & トーン (企画書 10.5 / 10.6)

| 場面 | トーン |
|---|---|
| コピー全般 | カジュアル、でも誠実 |
| エラー | システム側の問題として謝る(「お手数ですが…」) |
| 登録フロー | 温かみ・「ようこそ」感 |
| データ表示 | 客観的・断定的だが**憶測を避ける** |

**使ってはいけない表現**: 「絶対」「No.1」「最強」/「実力アップ」/「メーカー公認」/
製品の貶し/「初心者は◯◯すべき」。偽データ・水増しは禁じ手。

主要コピー: キャッチ「ラバー、結局どっちが自分に合うのか。」/ タグライン「卓球用具のAB比較。」/
プロミス「データで、用具選びの後悔を減らす。」

## 5. 実装方針

### 5.1 shadcn/ui 導入
- Tailwind v4 + React 19 対応構成で `src/components/ui/` にプリミティブを取り込む。
- テーマは新規の HSL 変数を増やさず、既存 `tt-*` トークンへマッピングする(色の二重管理を避ける)。
- まず Button / Card / Badge / Input / Select / Tabs / Dialog から。複合UI(VersusBar等)は自前を維持。

### 5.2 トークンの拡張(globals.css)
- 角丸・elevation の意味づけ(本書 1.4/1.5)に沿って、必要なら `--radius-*` を追加。
- `prefers-reduced-motion` でアニメーションを抑制するルールを追加。

### 5.3 移行(段階適用・回帰を出さない)
1. プリミティブ導入 → 2. トップ/カタログ/play/switch の順に置換 → 3. `text-[10px]`/`rounded-3xl`/
   余分な `shadow-sm` の掃除。各段階で `pnpm lint && pnpm test && pnpm build` を green に保つ。
- 独立評価サイクルの運用と両立: 見た目変更でコア機能(種類分離・データ正直さ)を壊さない。
