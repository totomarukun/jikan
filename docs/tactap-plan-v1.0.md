## 1. エグゼクティブサマリー

### サービスの一言定義

**卓球用具のAB比較データを通じて、自分に合う用具を可視化するゲーミファイドなSNS型サービス。**

### コアアイデア

ユーザーは「ラバーA vs ラバーB、どっちが好み？」という形のAB比較に3秒で答える。回答を重ねるほど、自分のスタイル診断や類似ユーザーの選好データがアンロックされ、最終的に「**自分と似たプレイヤーが選んでいる用具**」を知ることができる。

### 3つのコアバリュー

1. **似た人の選択がわかる**: プレースタイル・レベル・ラケットが類似したプレイヤーの選好を表示
2. **3秒で1問の軽さ**: SNSを開く感覚で参加できる
3. **失敗を減らせる**: 絶対評価より精緻な「相対比較データ」で用具選びの意思決定が変わる

### 既存サービスとの最大の差別化

国内外の卓球レビューサービス（卓球ナビ、Revspin、TableTennisDaily等）は**絶対評価＋自由記述**形式。本サービスは**AB比較（ペアワイズ）形式**で、評価の基準点問題を解決する。これは国内外を問わず空白地帯。

### MVP のスコープ

- 期間: 4〜5ヶ月
- 主要機能: AB比較体験、スタイル診断、用具対決ビュー
- 用具マスタ: 約120〜180製品
- ターゲット: 中級者中心、全レイヤー横断

## 2. 背景と課題

### 2.1 市場背景

卓球は国内競技人口が約700〜800万人と推定される普及スポーツ。用具（ラケット・ラバー）の選択がプレーに大きく影響し、多くのプレイヤーが「用具選びに迷う」状態にある。これは「沼」と表現されるほどのペインポイント。

### 2.2 ユーザーが直面している5つの構造的問題

| 問題 | 内容 |
|---|---|
| **組み合わせの爆発** | ラケット × フォアラバー × バックラバー × スポンジ厚で、理論上数万通り |
| **主観性の高さ** | 「弾む」「球持ち」などの感覚言語が標準化されていない |
| **個人差変数** | プレースタイル、スイング、打点で同じ用具でも使用感が変わる |
| **比較不能性** | 既存レビューは絶対評価で書かれるため、基準点が見えない |
| **ラケット影響の見えなさ** | ラバーレビューにラケット情報が紐付かず、比較精度が下がる |

### 2.3 ユーザーの典型的な「あるある」

- レビューを書いている人と、自分はレベルが違う気がする
- ラバーを変えたら、想像と全然違って後悔した
- 用具店で相談しても、結局自分で決められない
- YouTuberの試打動画は、自分のプレーには参考にならない
- 「弾む」「球持ち」って、人によって意味が違いすぎる

## 3. 市場・競合分析

### 3.1 既存サービスマッピング

| サービス | 国 | 主な機能 | 弱み |
|---|---|---|---|
| 卓球ナビ | 日本 | レビュー（ラバー約16,000件、ラケット約8,500件）+ EC | 絶対評価＋自由記述、類似度フィルタなし |
| Revspin | 米国 | ラバー・ブレード・台のレビュー28,000件以上 | UI古い、類似度マッチングなし |
| TableTennisDaily | 英国 | フォーラム形式の長文レビュー | 検索性が低く、UGCの構造化が弱い |
| Equipment Recommender | 個人開発 | プレースタイル診断型推薦ツール | 単一管理者の主観依存、データ駆動でない |
| Racket Insight | 豪州 | プレイスタイルクイズ付きメディア | パーソナライズ限定的 |
| Table Tennis Equipment Help | 個人 | 人力推薦コンサル（有料） | スケールしない |
| 卓球Lab | 日本 | 用具考察記事 | 個人主観中心 |

### 3.2 競合分析からの示唆

- **レビューデータベース**自体は既に飽和（卓球ナビ + Revspinで日米カバー済み）
- **「自分との類似度フィルタ」**を機能として持つサービスは国内外問わず存在しない
- **AB比較（ペアワイズ）形式**を採用しているサービスも存在しない
- 既存プレイヤーは絶対評価＋自由記述の枠から抜け出していない

### 3.3 本サービスの差別化ポジション

| 軸 | 既存サービス | TacTap |
|---|---|---|
| データ形式 | 絶対評価＋自由記述 | **AB比較（ペアワイズ）** |
| 投稿コスト | 数分〜10分 | **3〜10秒/問** |
| 類似度マッチング | なし | **あり**（プレースタイル × レベル × ラケット系統） |
| ラケット影響の扱い | 個別レビューに混在 | **層別変数として明示** |
| 価値提供 | 投稿者側にインセンティブ | **回答するほどアンロックされる体験** |

## 4. プロダクトコンセプト

### 4.1 サービスフロー全体像

```
[投稿フロー: 登録不要]
SNS流入 → 前提質問3問（9秒） → AB比較を1問ずつ回答
  → 5/10/20問達成で報酬アンロック
  → 30問達成でスタイル診断
  → 登録誘導

[閲覧フロー: 登録ユーザー]
登録 → マイページ → 用具対決ビュー（集計データ閲覧）
  → AB比較に追加回答（フライホイール）
```

### 4.2 ブランドプロミス

**「データで、用具選びの後悔を減らす。」**

すべての機能、コピー、デザイン判断はこの一文に照らして決定する。

### 4.3 ブランドパーソナリティ

| 軸 | 位置 |
|---|---|
| 真面目 ⇔ 遊び心 | やや真面目寄り（データ重視） |
| 専門的 ⇔ 大衆的 | バランス（中級者中心） |
| 革新 ⇔ 伝統 | やや革新寄り |
| 温かみ ⇔ クール | やや温かみ寄り（個人開発の人格） |
| 熱量 ⇔ 落ち着き | やや熱量高（卓球愛が滲む） |

キーワード: 誠実 / 軽やか / オープン / 卓球愛 / 賢い

## 5. ターゲットユーザー

### 5.1 ペルソナ

| ペルソナ | 中級者（メイン） | 初級者 | 上級者・競技者 |
|---|---|---|---|
| 特徴 | 用具沼に入りかけ、複数候補で迷う | 1本目を選ぶ、何を選べばわからない | 細かい調整、組み合わせ最適化 |
| 主要ニーズ | 自分に合う乗り換え先を知りたい | 失敗しない選択をしたい | 微妙な差分を可視化したい |
| WTP（支払意思） | 高 | 中 | 中〜高 |
| ボリューム | 大 | 大 | 中 |

**最優先ターゲット: 中級者**。WTP・課題の切実さ・市場規模のバランスが最も良い。

### 5.2 想定外ターゲット（明示的に外す）

- 完全な観戦専門ユーザー（プレー経験ゼロ）
- 卓球ロボット・台などの大型用具を選ぶユーザー（MVPの対象外）

## 6. プロダクト仕様（機能要件）

### 6.1 MVP機能スコープ（MoSCoW分析）

#### Must Have（必須）

| # | 機能 | 概要 |
|---|---|---|
| F1 | AB比較カード出題 | 投稿者プロファイルに基づいた質問生成 |
| F2 | 前提質問（3問） | レベル・プレースタイル・ラケット系統 |
| F3 | 匿名投稿対応 | 未登録でも回答可能 |
| F4 | 回答進捗・アンロック | 5・10・20・30問の報酬アンロック |
| F5 | ユーザー登録 | メアド／SNSログイン、匿名→登録のデータ引き継ぎ |
| F6 | 用具対決ビュー | 任意の2用具を選んで集計を表示 |
| F7 | 用具マスタ | 主要120〜180製品の基本情報 |
| F8 | マイページ | プロフィール編集、回答履歴 |

#### Should Have（あれば良いが後追い可）

- 用具個別ページ
- マイ傾向分析
- SNSシェア機能（OGP動的生成）

#### Could Have（Phase 3以降）

- 用具エクスプローラー（散布図ビュー）
- トレンドビュー
- 自動推薦機能
- コミュニティ・DM
- EC連携・アフィリエイト

> 補足（サイクル21 / M8）: 基準ゼロの初心者向け「はじめの基準（参考）」は、上記
> 「自動推薦機能」とは**別物**として扱う。前者は用具を断定的に勧める推薦ではなく、
> **相対地図に入るための原点（現在地マーカー）を供給する入口補助**であり、コア価値
> 「相対的に分かる」に直結する。実装は「参考・複数・非断定」に限り、提示後の主動作は
> 「これを基準に用具マップを見る」。推薦機能と混同して断定的レコメンドへ流さないこと。

#### Won't Have（明示的に切る）

- ネイティブアプリ（Webファースト）
- 動画レビュー
- 戦績管理・大会情報
- メーカー公式スペックの自動取込

### 7.3 各画面の詳細仕様

#### M1: ランディング画面

**URL**: `/`

**目的**: SNSやWeb検索からの着地点。3秒以内に「何のサービスか」を伝え、回答を開始してもらう。

**コンテンツ要素**:
- ロゴ（中央）
- キャッチコピー: "ラバー、結局どっちが自分に合う？"
- サブコピー: "3秒のAB比較で、あなたに合う用具がわかる。"
- プライマリCTA: "始める（無料）"
- 補助: "登録なしで参加できます"
- ログインリンク（既存ユーザー向け）

**遷移**:
- 「始める」 → M2
- 「ログイン」 → ログインフォーム

---

#### M2: 前提質問（3問）

**URL**: `/onboarding`

**目的**: AB比較のコンテキスト情報を取得。9秒以内に完了することが許容ライン。

**質問項目**:

| Q# | 質問 | 選択肢 |
|---|---|---|
| Q1 | 卓球レベルは？ | 初級／中級／上級／プレーしない |
| Q2 | プレースタイルは？ | ドライブ主戦／前陣速攻／カット／その他／決まっていない |
| Q3 | 使っているラケットの系統は？ | アウターカーボン／インナーカーボン／合板／粘着用／わからない |

**UI要素**:
- プログレスバー（3問中の何問目か）
- 質問テキスト（16-18px、weight 500）
- 選択肢ボタン（縦並び、各40px高さ）
- 「次へ」「戻る」ナビゲーション

**重要**: 「わからない」「決まっていない」を必ず用意（初級者の離脱対策）

#### M3: AB比較カード（最重要）

**URL**: `/play`

**目的**: サービスの中核体験。3〜5秒で1問回答可能な軽量UIで、繰り返し回答してもらう。

**画面構成**:

```
[ヘッダー（固定）]
- 進捗（X / 30問）
- プログレスバー
- 「あとN問で診断アンロック」テキスト
- コンテキスト表示: "条件: アウターカーボン × 中級"

[メインカード]
- 質問テキスト（例: "中陣ドライブで威力を出すなら？"）
- 用具A カード（青系背景）
  - 用具名、メーカー、種別、スポンジ厚
- "VS" 区切り
- 用具B カード（コーラル系背景）
  - 同上

[アクションエリア]
- 1段目: [Aを選ぶ] [Bを選ぶ]
- 2段目: [同じくらい] [わからない]

[回答後]
- 経験フラグ選択（モーダル or インライン）:
  - 両方使ったことがある
  - 片方だけ使ったことがある
  - どちらも使ったことはない（イメージで回答）
```

**カードバリエーション**（出題比率）:

| パターン | 比率 | 内容 |
|---|---|---|
| シンプルAB | 70% | 「どちらが好み？」 |
| 軸指定AB | 20% | 「スピードが速いのはどちら？」 |
| シナリオAB | 10% | 「バック面で使うなら？」 |

**評価軸**:

| カテゴリ | 軸 | 必須/任意 |
|---|---|---|
| コア | スピード | 必須 |
| コア | スピン | 必須 |
| コア | コントロール／総合好み | 必須 |
| 拡張 | 球持ち | 任意 |
| 拡張 | 硬さ（中立軸） | 任意 |

**バックエンド要件**:
- 次のカードを動的生成（質問生成アルゴリズムに従う）
- 直近10問と重複しないようフィルタ

**遷移**:
- 回答完了 → 経験フラグ選択 → 次のカード
- 5/10/20問達成 → M4
- 30問達成 → M5

#### M5: スタイル診断画面

**URL**: `/diagnosis`

**目的**: 30問達成の集大成。登録誘導の最重要画面。

**画面構成**:

```
[ヘッダー]
- 30 / 30問達成

[診断結果カード（メイン、グリーン系背景）]
- "あなたの卓球用具スタイル" ラベル
- スタイル名（例: "スピン重視・コントロール志向型"）
- 該当率（"全プレイヤーの14%が該当"）

[傾向スコア（3項目）]
各項目: ラベル + 数値 + 中立軸バー
- スピン > スピード: +1.8
- 硬めの打感: +1.2
- コントロール重視: +0.9

[CTA]
- プライマリ: "登録して詳細レポートを見る"
- セカンダリ: "Xでシェア"
- ターシャリ: "登録せず続ける"
```

**シェア時の文言例**:
```
私の卓球用具スタイルは「スピン重視・コントロール志向型」でした！
全プレイヤーの14%が該当するタイプ。
あなたも診断してみる→ [URL]
```

**スタイル推定ロジック（MVP簡略版）**:
- スピン vs スピードの選好カウントから「スピン重視/スピード重視/バランス型」を判定
- 硬さの選好から「硬め/柔らかめ/中立」を判定
- コントロール重視度から「コントロール志向/攻撃志向」を判定
- 数パターンの組み合わせでスタイル名を出力

#### L2: 用具対決ビュー

**URL**: `/compare/[aId]/vs/[bId]`

**目的**: サービスのコア価値。集計データを見せる画面。

**画面構成**:

```
[ヘッダー]
- 対決: 用具A vs 用具B

[フィルタ]
- 現在の絞り込み: "あなたと似た人で絞り込み"

[集計結果（3軸）]
- 好み: A vs B のバーチャート（n=X件表示）
- スピード: 同様
- スピン: 同様
```

### 8.2 重要な設計判断

#### 匿名→登録の引き継ぎ

匿名ユーザーの回答は `sessionId` をキーに保存する。登録時に `sessionId` を `userId` にマージする処理が必要。

#### 経験フラグの活用

`hasActualExperience` を分離することで、集計時に「実体験データのみ」「全データ」を切り替え可能になる。実体験データはハイクオリティ、イメージデータはマーケティング価値があり、両方とも保存する。

#### PairwiseStatのキャッシュ戦略

L2 対決ビューのパフォーマンス対策として、集計結果を `PairwiseStat` テーブルにキャッシュ。Phase 2.0 では Comparison から動的集計してもOK。データ増加に応じてキャッシュへ切り替え。

## 9. 質問生成アルゴリズム

### 9.1 3レイヤー戦略

M3 で次のカードを生成する際、以下の比率で3つのレイヤーから出題する。

| レイヤー | 比率 | 内容 |
|---|---|---|
| Layer 1: 関連性 | 60% | 投稿者プロファイルに合うペア |
| Layer 2: データ補完 | 30% | サービス全体で不足しているペア |
| Layer 3: 探索 | 10% | 興味を広げるペア |

### 9.2 Layer 1: 関連性レイヤー（60%）

投稿者のプロファイルに合うペアを優先。

**関連性の判定軸**:

| 関連性 | 判定条件 |
|---|---|
| 超高関連 | 投稿者が現在使用中の用具 vs 別の用具 |
| 高関連 | 投稿者と同じプレースタイル・レベル帯の人気上位用具 |
| 中関連 | 投稿者と同じラケット系統で使われやすいラバー同士 |
| 低関連 | プレースタイルは違うが、価格帯が近い用具 |

### 9.3 Layer 2: データ補完レイヤー（30%）

サービス全体でデータが不足しているペアを優先。

**補完優先度の計算式**:

```
補完優先度 = 1 / (現在の回答数 + 1) × (人気度A × 人気度B)
```

人気度は「ユーザーの使用率」または「回答対象になった回数」で代用可能。

### 9.4 Layer 3: 探索レイヤー（10%）

投稿者のプロファイル外のペアを意図的に混ぜる。回答率は低くて当然で、データ収集以上に「ユーザーの世界観を広げる体験」として機能する。

### 9.5 共通フィルタ

すべてのレイヤーで以下を適用:
- 直近10問のペアと重複しないようフィルタ
- 同一カテゴリ（ラバー or ラケット）に限定

### 9.6 MVP での簡略化

Phase A では完全ランダム（重複除外のみ）で開始してOK。Phase B で3レイヤー戦略を実装。

## 14. ローンチ戦略

### 14.1 ローンチ前: Smoke Test

正式ローンチ前にランディングページのみで需要検証:

- LP作成（STUDIO/Framer等で1週間以内）
- Twitter広告（5,000〜30,000円）でメアド登録を測定
- 1〜2週間のテスト期間
- CVR 5%以上が成功ライン

### 14.2 3段階ローンチ

| フェーズ | 期間 | 目標 |
|---|---|---|
| Phase A: シード | Week 13-17 | 累計500回答、ユニーク50人 |
| Phase B: 拡散 | Week 18-25 | 月次新規200人、バイラル係数 0.7+ |
| Phase C: 定着 | Week 26〜 | フライホイール定着 |

### 14.3 Phase A 施策（シード）

1. **作り手自身による回答**: 100〜200問
2. **卓球友人・知人への依頼**: 10名以上
3. **卓球コーチ・専門店との連携**: 3〜5店舗

特に**3. コーチ・専門店連携**は、質の高いシードデータが手に入る最強の施策。

### 14.4 Phase B 施策（拡散）

1. **SNS拡散コンテンツ**: 診断結果シェア機能、動的OGP
2. **卓球YouTuberコラボ**: 中規模YouTuber（卓キチちゃんねる、ユージくん等）
3. **Twitter上での話題化**: 毎日のAB比較投稿
4. **卓球メディア掲載**: Rallys等への記事化働きかけ

### 14.5 バイラル設計

**バイラル係数 K = (1ユーザーが招待する人数) × (招待された人が登録する確率)**

K ≥ 1.0 でフライホイールが回る。

仕掛け:
- 診断結果のシェア機能（シェアしやすい結果画面）
- 「友達と結果を比べる」機能
- インフォグラフィック型の結果表示
- 未登録でも結果を一部見られる

## 15. ビジネスモデル

### 15.1 短期（Phase B-C）

**完全無料**でユーザーを集めることに集中。収益化は意図的に後回し。

### 15.2 中期（10,000ユーザー規模到達後）

| モデル | 内容 | 優先度 |
|---|---|---|
| アフィリエイト | EC（Amazon、楽天、卓球専門店）への送客 | 高 |
| メーカー向けデータ提供 | 用具の選好データを匿名化してメーカーに提供 | 中〜高 |
| プロ向けサブスク | コーチ・専門店向けの分析ダッシュボード | 中 |
| 広告枠 | メーカー新製品のスポンサー表示 | 低（UX毀損リスク） |

### 15.3 ビジネスモデル選定の原則

- ユーザー体験を損なわないことを最優先
- データの中立性が崩れる施策（メーカー忖度等）は避ける

## 16. リスクと対策

| リスク | 対策 |
|---|---|
| シードユーザーが集まらない | Smoke Testで早期検証、コーチ・店舗営業を並行 |
| データの偏り（メーカー、レベル等） | 質問生成のLayer 2で補完 |
| 中上級者データの不足 | コーチ・専門店連携で重点獲得 |
| バイラルが起きない | 結果画面UXに投資、A/Bテスト |
| 卓球ナビ等の競合参入 | 差別化機能（AB比較、Eloレーティング）の先行優位 |
| ラケット影響を無視されないか | 系統カテゴリの分かりやすさに投資 |
| メーカーとの関係悪化 | データの中立性、ネガティブ表現の抑制 |
| 初級者の離脱 | 「わからない」「決まっていない」を全質問に用意 |

## 17. 用語集

| 用語 | 定義 |
|---|---|
| AB比較（ペアワイズ比較） | 2つの用具のうち、どちらが好みか／特定軸で優れているかを回答する形式 |
| Eloレーティング | チェスのレーティング方式。1対1の勝敗から個体スコアを推定するアルゴリズム |
| 協調フィルタリング | ユーザーの行動データから「似たユーザー」を見つけ、推薦に使う手法 |
| バイラル係数（K-Factor） | 1ユーザーが平均何人を新規ユーザーとして連れてくるかの指標。1.0以上で指数成長 |
| Smoke Test | プロダクト開発前にランディングページのみで需要を測るテスト手法 |
| アウターカーボン | ラケットの表面側に特殊素材（カーボン等）を配置した構造。弾みが強い |
| インナーカーボン | ラケットの内側に特殊素材を配置した構造。球持ちとのバランスが良い |
| 粘着ラバー | 表面が粘着性を持つラバー。中国系プレイヤーが多用 |
| 経験フラグ | AB回答時に「実際に両方使ったか／イメージか」を記録するフラグ |
| 3レイヤー戦略 | 質問生成を関連性60%・補完30%・探索10%の比率で行う設計 |
