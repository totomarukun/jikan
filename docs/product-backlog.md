# TacTap プロダクトバックログ (PM管理)

運営方針: 超リアルなペルソナによる外部評価サイクルを回し、
大玉から徹底的に改善する。機能の改廃も躊躇しない。

## 評価サイクル記録

| # | ペルソナ | 実施 | スコア | 主要発見 |
|---|---|---|---|---|
| 1 | 高橋健太 (34・上級・ドライブ・ディグニクス使い) | 済 | 3.5/10 | 厚さ上書きバグ / n=1ランキング有害 / 正規化値が信頼毀損 / 面跨ぎ比較 / 回答が資産にならない |
| 2 | 高橋健太 (同・アンカー再評価) | 済 | 必需5 / 手軽6 / 手間5 | 前回5指摘中4が解消を確認。新規: switchの無反応感 / n=1断言が用具ページ等に残存 / 重複登録ガード |

### サイクル2 対応 (全て実装済み)
- /switch: 候補追加は機能していることを再現確認 (516msで表示)。
  「無反応に見える」問題として loading スケルトンを追加
- n<3 の断言表示を全面禁止: 体感プロファイルは「まだ回答X件 — 集計中」、
  関連対決リスト(用具ページ/対決ビュー/ランディング)は集計中表示に統一
- ギア重複登録ガード: 登録済みラバー選択時に前回条件をプリフィル + 警告表示
- /gear のペア数見積もりを同面ペア基準に修正
- explore切替時にギア追加を強く誘導するバナー (実体験質問+5問の提示)

### サイクル1 対応 (全て実装済み)
- 厚さ上書きバグ修正 (再追加で既存詳細を保持)
- ギア出題を同面ペアのみに制限 + 直前ペア連続回避
- /battles・ランディングを n>=3 のみ表示 (未満は「集計中」)
- 独自0-100正規化値の表示を全廃 (公称硬度は「自社基準」明記、他社間は差分非表示)
- 勝率→「好み」勝率に明確化
- 回答の資産化: 開示パネルに+1表示、/gear に「あなたの体感メモ」(ペア×軸の自分の回答一覧、実体験バッジ付き)

### 評価基準 (ユーザー指示)
3指標すべて 9/10 以上で合格: ①絶対になくてはならない度 ②手軽さ ③手間のなさ

## PM仮説バックログ (ペルソナ評価と突き合わせて優先度決定)

### 大玉 (体験の根幹)

- [ ] **B1: 回答が資産にならない問題**
  10問答えても「自分に何が残るか」が見えない。マイギア間の自分の
  体感マップ (「自分はD05よりロゼナが好みだった」の一覧) を
  マイページ/ギアページに常設し、回答=自分のレビュー資産になる構造へ。
- [ ] **B2: 公称スペック数値の信頼性**
  0-100正規化した「公称値」は上級者には出所不明の数値に見える。
  メーカー間比較不能なのは業界常識。→ 数値表示をやめ相対表示にする
  / 「参考値」の出所を明示 / もしくは集計データのみに絞る判断。
- [ ] **B3: バック面文脈の弱さ**
  裏裏ドライブでもF/Bでラバー選定基準は別物。出題・switch・体感翻訳に
  面の文脈を通す (現状: ギアに面はあるが、switchは現用FH基準のみ)。
- [ ] **B4: コールドスタートの正直さ**
  n=0〜1のバーだらけだと信頼を失う。データ無し時の表示哲学を統一
  (「まだ無い」を堂々と見せ、貢献を促す)。

### 中玉

- [ ] M1: 診断のシェア画像 (動的OGP) — 流入の核
- [ ] M2: 用具ページの「同条件レビュー」絞り込み (厚さ・面)
- [ ] M3: ギア登録の摩擦低減 (人気ラバーのワンタップ候補)
- [ ] M4: battles と compare/select の役割重複の整理 (改廃候補)

### 運用

- [ ] O1: 本番スモークテスト (ネットワーク許可後)
- [ ] O2: 楽天/Amazon API での実写真・実価格 (要ユーザーのAPIキー)
