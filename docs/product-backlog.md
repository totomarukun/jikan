## PM仮説バックログ (ペルソナ評価と突き合わせて優先度決定)

### 大玉 (体験の根幹)

- [ ] **B1: 回答が資産にならない問題**
  10問答えても「自分に何が残るか」が見えない。マイギア間の自分の
  体感マップ (「自分はD05よりロゼナが好みだった」の一覧) を
  マイページ/ギアページに常設し、回答=自分のレビュー資産になる構造へ。
- [ ] **B2: 公称スペック数値の信頼性**
  0-100正規化した「公称値」は上級者には出所不明の数値に見える。
  メーカー間比較不能なのは業界常識。→ 数値表示をやめ相対表示にする
  / 「参考値」の出所を明示 / もしくは集計データのみに絞る判断。
- [ ] **B3: バック面文脈の弱さ**
  裏裏ドライブでもF/Bでラバー選定基準は別物。出題・switch・体感翻訳に
  面の文脈を通す (現状: ギアに面はあるが、switchは現用FH基準のみ)。
- [ ] **B4: コールドスタートの正直さ**
  n=0〜1のバーだらけだと信頼を失う。データ無し時の表示哲学を統一
  (「まだ無い」を堂々と見せ、貢献を促す)。

### 中玉

- [ ] M1: 診断のシェア画像 (動的OGP) — 流入の核
- [ ] M2: 用具ページの「同条件レビュー」絞り込み (厚さ・面)

- [ ] M4: battles と compare/select の役割重複の整理 (改廃候補)
